# Offline checks for the SC engine (no audio hardware, no GUI)

These scripts run the F2 engine under `sclang` and render audio with scsynth in
non-realtime mode, so the DSP can be verified on a machine with no sound card.
They are a safety net for changes to `sc/f2units.scd`: they catch syntax errors,
UGen-graph errors, silent units and NaN/blow-ups before the engine is loaded in
the app.

## Setup (Debian / Ubuntu)

    apt-get install -y --no-install-recommends supercollider-language supercollider-server

`sc3-plugins` is optional for the engine and is what `extdeps.scd` measures. On
Debian and Ubuntu it is `apt-get install -y --no-install-recommends sc3-plugins-server
sc3-plugins-language`; the checks that render audio through the sampler's spectral mode or
the four `SVF` filter models need it, and every other check runs without it.

Run as a normal user (not root — Qt's sandbox refuses) with an offscreen
platform. Paths resolve from the script itself, so the working directory does
not matter; renders go to `$F2_NRT_OUT` (default `/tmp`), never into the repo:

    QT_QPA_PLATFORM=offscreen sclang -d /tmp -i none sc/nrt/compile.scd
    F2_NRT_OUT=/tmp/f2nrt QT_QPA_PLATFORM=offscreen sclang -d /tmp -i none sc/nrt/chain.scd

`headfwd.scd` renders nothing and needs no output directory — it opens the
front's UDP port itself and exits with its own verdict.

`live-banks.scd`, `live-ptrs.scd`, `live-hush.scd`, `live-decks.scd`,
`live-voices.scd`, `live-alloc.scd`, `live-smooth.scd`, `live-ports.scd`, `live-restart.scd` and
`live-modbus.scd` are the exception to "no audio hardware, no server": they NEED a live scsynth, because
what they check cannot exist offline. An NRT score is one
thread executing messages in timestamp order, while a real server hands
`/b_alloc` to its non-realtime thread and executes `/b_setn` immediately on the
realtime one — so a fill sent straight after an allocation lands on a buffer that
does not exist yet and is dropped without a word. Start any server and point the
script at it (no audio device is needed, and `-l 1` is not optional — without it
sclang's login handshake reports 64 clients and each client's slice of the buffer
numbers is too small for f2units to load at all):

    scsynth -u 57110 -a 1024 -b 4096 -l 1 -i 0 -o 2 &
    F2_LIVE_PORT=57110 QT_QPA_PLATFORM=offscreen sclang -d /tmp -i none sc/nrt/live-banks.scd

It reads `beat.wav` from `F2_NRT_SAMPLES` (default: the directory of the script),
renders nothing and prints its own verdict.

`live-hush.scd`, `live-decks.scd`, `live-smooth.scd`, `live-ports.scd` and
`live-restart.scd` want the boot's own headroom (`-a 16384`), because
`live-decks.scd` starves the audio-bus allocator on purpose in its last section
and `live-ports.scd` reads the allocator's own watermark after ten 32-channel
ports have been taken. `live-modbus.scd` wants the opposite and takes `-c 2048`:
its subject is a control-bus pool that has RUN OUT, and at the boot's own 1000000
the wall is out of reach.
Give each run a server of its own: with `-l 1` a client registration
outlives the `sclang` that made it for a moment, and a second run started
immediately behind the first is answered with `could not register, too many
users` and then `no scsynth answering` — which looks exactly like no server at
all. They all read the SERVER's own answer — `/g_queryTree` for the node tree,
`/c_get` for a control bus — rather than `Node:isPlaying` or a client-side
object: a client-side `isPlaying` lies in both directions — `false` for
a group the server created but nobody registered, `true` for a node the server
refused to create (`register(true)` assumes the `/n_go`) — and `~mbSyn[k]` stays
exactly as truthful after the node under it is gone. All three of those lies are
faults these scripts exist to catch; the second one is `live-restart.scd`'s
whole subject, and the engine now asks `isRunning` — which only a real `/n_go`
sets — rather than believing its own assumption.

`fragments.scd` needs no sample files at all: the three test buffers it wants — a
click, a noise burst and a chirp — are cheaper to build inside the score than to
read, and building them there keeps the check independent of `mksamples.py`.

`sampler.scd`, `sliced.scd`, `cycles.scd` and `analyze.scd` read the generated
samples from `F2_NRT_SAMPLES` (default: the directory of the script), so run
`mksamples.py` there first.
`sliced.scd` also RENDERS the slicing analysis: it spawns its own short NRT
passes over `beat.wav` and `line.wav` (the same ones `~f2SmpRes` kicks in the
app) and writes their scratch files into `F2_NRT_OUT` before the main render.

## What CI runs, and what it does not

Since §sc-deps the fast half of this suite runs on every push (`.github/workflows/ci.yml`,
job `engine`): `compile`, `extdeps` (with the plugin pack and, through
`no-extensions.yaml`, without it), `units`, `chain`, `rootkey`, `analyze`, `curveab`,
`sampler`, `sliced`, `cycles` and `fragments` — eleven checks, seconds each. The reason is measured rather
than theoretical: while nothing ran them, `fragments.scd` sat reading FAIL for months on a
control count that had simply moved, and the engine stopped compiling altogether on a
machine without sc3-plugins without anyone noticing.

What stays out of CI and remains a by-hand release gate: `build.scd` (about ten minutes for
its ~700 variants), the sweeps, `live-banks.scd`, `live-ptrs.scd`, `live-hush.scd`,
`live-decks.scd`, `live-voices.scd`, `live-smooth.scd` and `live-ports.scd` (they need a
live server), `variant-name.scd` and
`schema.scd` (both need nothing and take seconds — they are out only because the workflow has
no entry for them yet; `schema.scd` is half of a check whose other half runs in vitest, so
until it is wired in, the engine's side of the SC ≡ TS mirror is a by-hand gate), and the A/B checks —
`procab`, `convab`, `envab` — because each needs a REFERENCE
checkout in `F2_NRT_REF`, and which commit is the right reference is a judgement about what
the change was meant to alter. Note for `envab`: its `poly_ld_tap` case asserts a
difference, so it reads FAIL against any reference that does not straddle the tap change.

`sclang` exits 0 whatever a script decided, so a verdict is read from the TEXT, and it takes
BOTH halves. Every script prints `### …` on a failure and a closing line on success, and CI
requires the closing line as well as the absence of markers: a script that THROWS inside its
measuring pass prints neither — it stops, or hangs until the job's timeout — and a grep for
failures alone would call that a pass. Related trap, worth knowing before you write a check:
`1.exit` does not stop this sclang. The quit is deferred to the event loop and every statement
after it still runs, so a failure path has to be an `else` branch (or `1.exit; ^nil;` at the
top level of a block) rather than a fall-through.

## Test samples

`mksamples.py` writes three short WAV files with no dependencies beyond the
standard library, chosen so every slicing and play mode has something to chew on:
`beat.wav` (eight transients on a 120 bpm sixteenth grid), `line.wav` (four
pitches with a glide in the middle) and `pad.wav` (a stereo drone). They are
generated rather than committed, so the repository stays free of binaries. The
checks read them MONO (`/b_allocReadChannel`, the shape `~loadSamples` gives the
engine): `GrainBuf` needs a mono buffer and a tape reader would interleave the
channels of a stereo one.

## Known non-failures

Four processors are silent when fed only by `chainIn`, by design, and sound as
soon as their other input exists:

- `convU` needs a kernel buffer on `kerIn`
- `vocU`, `xspecU` need a modulator on `modIn`
- `pluckU` plucks on the GATE opening, so it must be spawned with `gate 0` and
  opened afterwards (which is exactly what the voice pool does)

## Notes

- The scripts pre-seed `~f2FlatWin` with a bare `Buffer` because
  `Buffer.loadCollection` needs a running server; the wavetable bank is
  reproduced as `/b_alloc` + `/b_gen sine1` messages inside the score.
- Every `polysynthU` def is larger than 16383 bytes, and so is `polymerU`'s
  base def since its `ld` arm carries the taps and the AGC (11877 → 18560
  bytes), so sclang writes a def file and `/d_load`s it instead of `/d_recv` —
  fine for a local server, which is what F2 uses. The sampler's keyless base
  stays under the line (16158); its heavier filter variants (`vowels` +13.6 kB,
  `ripple` +8.7 kB, `xp` +6.4 kB, `ld` +5.8 kB) cross it.
